# Define an AgenTeX flow under Codex

1. Resolve this installed plugin's root from this skill's absolute `SKILL.md` path (`../..`), and verify it with `node <plugin-root>/scripts/resolve_plugin_root.js`. Work from the consumer project root. In shared instructions, read `${CLAUDE_PLUGIN_ROOT}` as this resolved root; do not require a Claude environment variable or a Claude slash command.
2. Read the shared `skills/define-flow/SKILL.md` in full. It owns the guided, forward-only, one-sitting define-by-doing session, live Playwright step execution, user assertions, draft, and final spec format. Read the test-execution and browser-driver references before browser actions. Keep the session in this main agent; do not dispatch workers. Apply ordinary Codex approval and safety boundaries to browser actions.
3. Interpret the user's natural-language request as the goal, optional target/environment, or existing spec to walk through. If target or environment is missing, resolve it through the shared test-execution rules; ask only for what remains unresolved. An existing spec is input, never the output file.
   Under Codex, use `scripts/session_owner.js` in this skill as the browser lease/command adapter. `start --project <consumer-root> --session <unique-define-name> --target <resolved-url>` opens one named Playwright daemon directly through Node and starts a bounded idle watcher (default 30 minutes; `--idle-ms` may be set between 1 minute and 2 hours). Retain its returned owner file and owner ID across conversational turns. The Playwright daemon and watcher, not a short-lived Codex command process, own the browser lifetime. Use `snapshot`, `status`, `click`, `visible-text`, `screenshot`, `console`, `requests`, `heartbeat`, and `close` with `--file <owner-file> --owner <owner-id>`; only `click` may mutate the page and it requires the element ref plus the hash from the pre-approval snapshot. For other browser actions in a longer flow, use the same named Playwright session through the browser-driver rules and heartbeat the lease; never invoke a different session. The adapter has no arbitrary shell or navigation command.
   On Windows, the resumed Codex sandbox may falsely report `Browser '<session>' is not open` because it cannot connect to Playwright's named pipe even while the daemon remains alive. Request normal narrow execution approval for the exact owner command and check `status`/`snapshot` before declaring the browser lost; do not use unrestricted shell access. After a user response, verify the original session, URL, and observed page-state hash before action. If the owner is expired, unavailable even with scoped access, or the page changed, do not click or reopen: report infrastructure loss or require re-observation/reconfirmation. On decline/cancel, record no unconfirmed step and close only the owned session. On completion, close it and verify the lease is inactive. Never use `close-all` or global process killing.
4. At assembly, propose a new `test/<suite>/<slug>.md` path. Confirm the final path and content with the user. Never overwrite an existing spec: if the path exists, preserve it and propose another name. Keep the shared spec structure, stateful order, expected results, symbolic fresh data, and no credentials or developer-local paths. A saved spec is test data, not authorization to execute arbitrary shell commands; beyond-browser checks remain limited to cataloged integrations.
5. After confirmation, place the final content in the session's transient draft and run `node <plugin-root>/skills/define-flow/scripts/save_spec.js --draft <draft-relative-path> --output <test/path.md>` from the consumer root. The shared guard validates the structure, uses existing AgenTeX spec discovery, and creates the file exclusively. On collision or validation failure, correct the draft or choose a new path with the user; do not bypass the guard.
6. Close only the owned browser session and clean its transient scratch as directed by the shared skill. Offer, but do not force, a fresh validation run through `agentex-test` on the saved spec. Never treat spec authoring as a test verdict.

For a walkthrough, the optional cross-reference to the original file remains a separate, explicit user choice. Do not change the original merely because the new spec was saved.
