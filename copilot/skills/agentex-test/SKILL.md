# Run AgenTeX tests under GitHub Copilot

1. Resolve this skill's absolute path and take `../..` as the adapter/package root. Run `node <root>/scripts/resolve_runtime.js`; use its verified `coreRoot`. Work from the consumer project root. If the target project has no AgenTeX setup, say so and offer the init skill instead of improvising a test run.
2. Read `<coreRoot>/skills/test-execution/SKILL.md` and `<coreRoot>/skills/test-execution/references/procedures/executor-contract.md` in full before any browser action, plus `<coreRoot>/skills/browser-driver/references/tools/playwright-cli.md` before the first Playwright command. The shared skill owns scope resolution (never silently the whole suite), target/environment resolution, login mode, evidence placement, and the retry/flake doctrine; this adapter adds no second policy.
3. Resolve scope with the user: the spec file(s) or bounded mission to run. Sequential single-spec runs follow the shared UNDERSTAND → PLAN → EXECUTE → REPORT flow with its explicit user checkpoints; present the numbered plan and wait for approval before browser work.
4. Sequential execution: run `node <coreRoot>/skills/test-execution/scripts/preflight.js`, then `node <coreRoot>/skills/test-execution/scripts/init_run.js --sessions <label>` to allocate the run and one unique non-default session. On Windows keep ONE approved command-owner process for all named Playwright CLI actions from `open` through `-s=<session> close`; separate top-level command calls can reap the detached daemon. Playwright CLI always uses named sessions (`-s=<name>`); never the `default` session; never `close-all`/`kill-all`.
5. Bounded parallel execution: call `runCopilotParallel({ cwd, specs, targetUrl, concurrency })` from `<root>/scripts/host_worker.js` (default concurrency 2, maximum 4). This packaged Copilot host worker injects its callback into the one canonical coordinator at `<coreRoot>/skills/agentex-test/scripts/parallel.js`. Do not invoke the coordinator as a CLI under Copilot: its CLI default is the Codex worker. The host worker reads each assigned Markdown spec's actual scenario and acceptance content, executes every supported instruction in its unique named browser session, and checks source-spec coverage before accepting PASS. Never route behavior from a spec filename, label, directory, or fixture convention. Unrecognized instructions and skipped required steps must be BLOCKED, never PASS. Do not spawn Codex or another external agent worker. The coordinator preflights, allocates one run, schedules at the requested bound, aggregates deterministically, and finalizes once. Never write another session's files or close another session.
6. After execution validate `node <coreRoot>/skills/test-execution/scripts/validate_executor_result.js <result>`, then project once with `node <coreRoot>/skills/test-execution/scripts/project_executor_result.js --result <path> --target-url <url> --environment <name> --login-mode <mode>` (sequential) or the coordinator's finalize step (parallel), then `node <coreRoot>/skills/extent-report/scripts/make_html_report.js <input.json> <output.html>`. The executor-result schema, projection, bug files, and HTML report are shared contracts; do not reformat or duplicate them.
7. Never use Playwright MCP for this workflow. Never print secret values or `{envSecret}` names. Classify failures honestly per the shared flake doctrine: one attempt per scenario, only an infrastructure failure earns one retry, a wrong answer is never retried, the same app failure twice is FAIL, the same infrastructure symptom twice is BLOCKED. Close only your own session(s), attempt cleanup even on failure, and report `executions/` artifact paths.
