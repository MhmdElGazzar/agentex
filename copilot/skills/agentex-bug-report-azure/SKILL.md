1. Resolve this skill's absolute path and take `../..` as the adapter/package root. Run `node <root>/scripts/resolve_runtime.js`; use its verified `coreRoot`. Work from the consumer project root. The shared files own the bug input contract, field mapping, duplicate check, evidence review, single approval, and write order. Use only the bundled `read-workitem.js`, `check-image.js`, and `create-bug.js`; do not compose Azure requests, use `az`, or implement a second bug writer.
2. Only use a user-selected local defect from a completed AgenTeX run, or a fully user-supplied manual defect. Test execution must never automatically file a bug. The server-side POST in plan mode is non-persistent. Show the target org/project, test-case list/count, and the exact `--execute` flags. Any changed payload, target, evidence bytes, or flag must be prepared and approved again. Never call the legacy unbound `--execute` form. Do not use `--allow-duplicate`, `--force`, or `--no-screenshots` without their own explicit disclosure and approval.
4. Report the returned ledger receipt exactly, including any created Bug ID after a later failure. A receipt marked complete, in-flight, or needs-reconciliation blocks replay of the same approved plan. Never retry a create, attachment, or relation automatically after a timeout or partial result; reconcile with Azure reads and ask the user for a new decision. A possible-duplicate or failed duplicate-check finding blocks filing unless the shared workflow's explicit exception is followed with its own approval. Never access an unrelated Azure project or application, and never print secrets.
