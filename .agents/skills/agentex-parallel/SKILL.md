# AgenTeX Codex native parallel test

When HEADED is explicitly requested, set `browserMode: "HEADED"` in the `host.js prepare` input. Otherwise HEADLESS is the default. For each browser assignment, the coordinator runs `host.js preflight <runRoot> <assignmentId>` and `parallel.js gate <runRoot> <assignmentId>` before native delegation. A nonzero result blocks dispatch. The worker reuses that session and routes every browser action through `host.js browser`, closing through `host.js browser-close`. The gate and guarded actions apply to both browser modes.

Use this only when the active Codex host exposes native subagent delegation and lifecycle observation. Use the host's actual `spawn_agent` mechanism; a CLI process, shell background job, or Node worker is not a substitute. If unavailable, report BLOCKED. Verify the available host subagent capacity for this turn, including other active agents. Never allocate more than `min(6, available capacity)` workers. A capacity refusal before attempting delegation may wait for a slot; a genuine failed launch is terminal for that assignment. Keep at most one worker per assignment.

1. Read `.agentex/codex.json`, `<pluginRoot>/skills/test-execution/SKILL.md`, its parallel procedure, and `<pluginRoot>/agents/qa-executor.md` for execution semantics. Apply the Codex path aliases and driver routing from `agentex-test`. Do not invoke Claude orchestration. Interpret the user's scenarios and original prose, and freeze every required interaction and assertion before dispatch. Use independent assignments for independent scenarios. Keep stateful scenarios together within one assignment.
2. Write a JSON input with absolute `projectRoot`, `mode: "parallel"`, verified positive `hostCapacity`, `scenarios`, and optional policy. Every scenario has one `spec` or `adHoc` and complete `requiredSteps` with stable `id`, `assertionIds`, and `evidenceRequired`. Call `node <pluginRoot>/scripts/codex/host.js prepare <input.json>`. Retain `custody.json` and every assignment file as coordinator-owned records. Use each returned assignment's own `sessionId`, `sessionDir`, and `resultFile`.
3. For each available browser assignment, first call `host.js preflight <runRoot> <assignmentId>` and require exit 0. Then call `parallel.js gate <runRoot> <assignmentId>` and require exit 0 and a persisted gate event. Complete both calls before invoking the native worker; a failed call blocks delegation. For non-browser assignments, no browser gate is needed. Only then call the Codex native delegation tool with the thin worker contract at `<pluginRoot>/scripts/codex/executor.md`, the exact assignment path and result destination. Record the returned native worker identity with `node <pluginRoot>/scripts/codex/parallel.js launch <runRoot> <assignmentId> <workerId>`. Track start and end times, wait for completions, and fill slots only within the verified limit. If delegation fails before returning a worker identity, call `parallel.js finish <runRoot> <assignmentId> launch-failed` directly; never invent a worker ID or launch timestamp. That assignment remains terminal and BLOCKED. If the host cannot inspect a worker's lifecycle, the run cannot PASS.
4. The worker writes only its own result and session evidence. On worker return, cancellation, timeout, or failure, call `parallel.js finish <runRoot> <assignmentId> <completed|failed|cancelled|timed-out|launch-failed>`. A `completed` event requires a result already on disk. A missing/late result, duplicate completion, or stale attempt is BLOCKED by the lifecycle check or shared validator. Never mark a failed product assertion PASS. Close only owned browser sessions and record actual cleanup.
5. After all workers finish, resolve any NEEDS-USER items at merge time using `<pluginRoot>/scripts/codex/ui-outcomes.md`: show the precise question and both image paths, retain the worker result, and call `host.js resolve` with the answer and validated final result before finalization. Unanswered questions stay BLOCKED; VIEW MISMATCH ERROR stays named and BLOCKED. Call `host.js finalize <runRoot> <assignmentId>` for submitted results. Keep nonzero validations; never prune failed or blocked assignments. Write actual run and scenario timing metadata in the same shape as `agentex-test`, then call `host.js report <runRoot> <metadata.json>` once as coordinator. It revalidates every assignment, checks lifecycle, and writes `run-summary.json`, `verdict.json`, `report.md`, and `extent-report.html`. Use its exit code 0/1/2. Verify observed worker execution intervals overlap before claiming concurrent execution. Report absent evidence as unverified, never inferred.

The unkeyed assignment digest detects drift but does not authenticate an attacker able to change both custody and assignment files. The coordinator must retain those files outside worker control.
The persisted gate and launch ledger validate recorded order. They cannot independently timestamp the native delegation call, which occurs in the host outside these Node scripts; report that runtime limitation until a native smoke observes the actual call sequence.
